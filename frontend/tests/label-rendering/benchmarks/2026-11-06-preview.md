# Designer preview benchmark, 2026-11-06

The SVG preview optimization makes warm edits image-ready 1.8–2.4× faster for
ordinary artwork labels on this machine. Print output is unchanged. Retained
JavaScript heap for artwork labels increases slightly; total RAM was not measured.

## Method

- Baseline: `d03bca09b2ba00ef54e61b12a584ba7a665c3a10` (QR/text/unit fixes already present).
- Candidate: `64555f1051c418e2c1e5505689539832525c928c` (SVG preview, artwork cache, sheet update routing and QR clearance validation).
- Apple M4 Max, macOS Darwin 27.0.0 arm64, Node 22.23.3, headless Chrome 157.0.8103.38; viewport 1440×1000, device scale 1, no CPU throttling.
- Immutable Git archives, identical dependency lockfile and installed dependencies, loopback Vite servers, synthetic labels. QR content is fixed so server ports cannot change output.
- Three alternating-order rounds per fixture/revision; eight warmups then 30 position edits per round (90 samples). Fresh browser page/context per round/fixture/revision. First-render timing excludes module imports.
- Processing ends when `renderDesignerLabel` resolves. Image-ready additionally awaits `img.decode()`; it excludes presentation/vsync. Export timings use five repetitions per DPI/mode per round.

Reproduce with the [benchmark command](../README.md#matched-preview-benchmark).
[Raw results](2026-11-06-preview.json) contain every sample, first-render latency,
environment metadata, heap readings and output hashes.

## Latency

All times are milliseconds. Artwork fixtures contain two text boxes, a decorated
QR and manufacturer logo. The text fixture contains 60 text boxes.

| Fixture | Processing median, before → after | Image-ready median, before → after | Image-ready speedup | Image-ready p95, before → after |
| --- | ---: | ---: | ---: | ---: |
| 60×40 mm, artwork | 24.9 → 2.2 | 25.1 → 13.6 | 1.85× | 26.2 → 18.5 |
| 100×70 mm, artwork | 32.6 → 2.2 | 32.8 → 13.5 | 2.43× | 33.5 → 15.3 |
| 280×180 mm, artwork | 99.9 → 2.1 | 100.3 → 13.6 | 7.38× | 102.9 → 15.1 |
| 100×70 mm, 60 text boxes | 19.5 → 4.7 | 20.0 → 7.3 | 2.74× | 21.0 → 7.9 |

First-render image-ready medians also decreased: 87.4 → 50.1, 98.7 → 49.2,
204.4 → 49.7 and 75.3 → 35.7 ms respectively. Repeated artwork decodes across
90 warm edits fell from 180 to zero for each artwork fixture.

Normal 300 DPI PNG export medians were 18.7 → 18.9, 25.7 → 26.4,
92.0 → 92.5 and 18.1 → 17.8 ms respectively. These small differences do not
establish an export speedup or regression; no confidence interval was estimated.

## Memory tradeoff

Artwork fixtures retain about **0.36 MiB more JavaScript heap** after forced GC
(approximately 5.10 → 5.46 MiB), consistent with caching prepared artwork and
keeping SVG preview state. The text-only fixture changed by −0.023 MiB.
For the small artwork fixture, median retained growth over 150 further edits was
0.103 MiB before versus 0.097 MiB after. Every preview Blob URL was revoked on
clear. This bounded run does not prove the absence of long-running leaks.
The production cache caps retained entries at 16 and estimated key/data strings
at 16 MiB. Native image buffers, GPU memory, process/peak RAM and mobile devices
were not measured; this is **not evidence of lower total RAM**.

## Regression checks

- **66 candidate print comparisons** across three rounds, normal/thermal modes and 203/300/600 DPI where within the 8-million-pixel budget: exact SHA-256 equality for SVG, PNG and packed mono1 output against baseline (198 matching hashes). Editor hitbox geometry also matched across every run.
- Clean candidate archive, excluding unrelated working-tree changes: **2,104 frontend tests / 130 files passed**, production build passed, Astro check reported zero errors/warnings and seven existing hints.
- Real Chrome editor checks: **114/114 passed**, including field units, dragging, sheet updates and localized QR clearance guidance. Application output checks passed PNG/PDF exports, print composition, editing, undo/redo and reload.
- **13 backend renderer/API tests passed**; **seven authenticated API/browser outcomes matched**, including final wire padding, rotation and thresholds.
- Unit tests guard SVG preview without interactive PNG rasterization, cache reuse/eviction/error recovery, preview URL cleanup, sheet-only updates without source rendering, and QR clearance conflicts. Existing CI runs frontend regression and browser output checks.

Interactive SVG antialiasing can differ from the former Resvg PNG preview;
strict export remains Resvg. This desktop headless benchmark is not a mobile,
full drag-to-screen frame-rate, physical print or scanner reliability test.
